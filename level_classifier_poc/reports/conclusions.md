# Выводы по PoC (hh.ru)

## Что сделано
- Выделены резюме IT-разработчиков (фильтр по ключевым словам в названии/навыках).
- Сформирована целевая переменная y: junior / middle / senior по названию должности и/или опыту.
- Построен график баланса классов.
- Обучен классификатор уровня (TF-IDF по title + табличные признаки: зарплата, город, возраст, опыт).
- Построен classification report (precision/recall/F1).

## Качество модели
По тестовой выборке получено:
- Accuracy ≈ 0.777
- Macro F1 ≈ 0.751
- Лучшее качество на классе senior (F1 ≈ 0.854).
- Наиболее сложный класс — middle (F1 ≈ 0.622), т.к. он “переходный” и сильнее пересекается с junior/senior.

## Возможные причины ошибок
1) Дисбаланс классов (middle представлен меньше остальных).
2) Эвристическая разметка y:
   - уровень может отсутствовать в названии,
   - опыт может быть общий (не по разработке),
   - возможны конфликты “title vs опыт”.
3) Ограниченность признаков: в данной выгрузке отсутствуют skills/description, поэтому модель опирается в основном на title и табличные поля.
4) Фильтр “разработчик” по ключевым словам может включать или исключать резюме с пограничными ролями.

## Почему PoC жизнеспособен
Даже на ограниченном наборе признаков модель различает junior/middle/senior с разумным качеством (macro F1 около 0.75), что показывает реализуемость автоматической классификации уровней по данным hh.ru.

## Как улучшить
- Добавить и обработать skills/description (TF-IDF по навыкам/тексту).
- Улучшить фильтр IT-разработчиков (точнее исключать админов/инженеров и т.п.).
- Использовать кросс-валидацию и подбор гиперпараметров.
- Сделать отдельный baseline без использования title (чтобы уменьшить “утечки” по словам уровня).
